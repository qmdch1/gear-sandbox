# Gear Sandbox — 설계 문서

- **날짜**: 2026-08-18
- **분류**: 아키텍처(architectural) — 신규 프로젝트
- **한 줄 요약**: 여러 종류의 톱니바퀴를 3D 공간에 드래그로 배치·연결하고, 손잡이 기어를 돌리면 맞물린 기어들이 함께 회전하며, 사용 시간에 따라 기어별 내구도가 소모되는 걸 눈으로 확인할 수 있는 웹 샌드박스.

## 1. 목적 & 범위

- **성격**: 목표/점수/클리어 조건이 없는 **샌드박스형 시뮬레이터**. 사용자는 자유롭게 기어를 배치·연결하고 결과(회전, 마모)를 관찰한다.
- **핵심 재미**: (1) 맞물린 기어들이 실제로 함께 도는 것을 보는 것, (2) 기어 종류별로 내구도가 다르게 닳는 걸 시간배율을 조절해가며 관찰하는 것, (3) 3D 공간에서 축이 꺾이는 구성(베벨/웜)을 실제로 만들어보는 것.
- **비목표(out of scope)**: 목표/점수 시스템, 멀티플레이어, 서버 백엔드(전부 클라이언트 사이드), 정밀 물리엔진 수준의 강체 시뮬레이션(자유낙하·충돌 등은 다루지 않음 — 오직 회전 전파와 마모만).

## 2. 대상 플랫폼

- 데스크톱 브라우저(마우스 드래그 + 휠 줌) + 모바일 브라우저(터치 드래그 + 핀치 줌). 둘 다 반응형 UI로 대응.
- 순수 클라이언트 사이드 웹앱. 백엔드/서버 없음.

## 3. 오브젝트 종류 (기어 패밀리)

| 오브젝트 | 설명 | 회전/동력 특성 |
|---|---|---|
| **평기어 (Spur gear)** | 이가 축과 평행한 기본 기어 | 맞물린 상대와 반대 방향으로 회전, 잇수비만큼 감/증속 |
| **헬리컬 기어 (Helical gear)** | 이가 비스듬히 나 있어 맞물릴 때 여러 이가 동시에 걸림 → 하중이 분산돼 개별 이의 데미지가 균등. 실제 자동차 변속기가 평기어 대신 이걸 표준으로 쓰는 이유와 동일 | 평기어와 동일한 회전 규칙, 기본 내구도가 더 높음 |
| **손잡이 기어 (Crank gear)** | 평기어에 손잡이가 달려 사용자가 직접 드래그/클릭으로 돌리는 구동원 | 트리 전체 회전의 시작점(동력원) |
| **베벨 기어 (Bevel gear)** | 축이 직각으로 만나는 기어 | 회전축의 방향을 90도 꺾어 전달 — 3D 배치가 실제로 의미를 갖게 하는 오브젝트 |
| **웜 기어 (Worm gear)** | 나사 모양 축(웜) + 웜휠 조합 | 감속비가 매우 크고, 웜휠→웜 방향으로는 역구동 불가(한쪽으로만 동력 전달) |
| **부하 오브젝트 (Load / Flywheel)** | 이가 없는 무게추/팬. 톱니와 맞물리지 않고 축에 부착돼 저항을 발생 | 자체 회전은 없고, 부착된 기어의 마모 속도를 높이는 부하 역할 |

각 타입은 고유한 기본 최대 내구도 값을 갖는다(정확한 수치는 구현 중 튜닝).

## 4. 연결(맞물림) 판정

- **유효 맞물림 조건**: 중심간 거리 ≈ 두 기어 피치반지름의 합(오차범위 내) AND 모듈(이 크기) 호환 AND 기어 패밀리별 축 방향 규칙(평/헬리컬/크랭크는 평행축, 베벨은 직교축, 웜-웜휠은 전용 규칙) 충족.
- **동력 전파**: 크랭크 기어를 루트로 한 그래프 BFS로 회전을 전파한다. 맞물려 있어도 크랭크까지 경로가 없으면 회전하지 않는다.
- **UI로 표기할 문제 상태**:
  1. **미연결** — 어떤 기어와도 안 맞물린 채 혼자 있는 기어
  2. **동력 없음** — 자기들끼리는 맞물려 있지만 크랭크까지 경로가 없는 고립된 무리
  3. **겹침** — 두 기어가 유효 맞물림 거리보다 가까워 기하학적으로 겹치는 경우(별도 경고)
- 표기 방식: 문제 있는 기어는 3D 씬에서 빨간 테두리/틴트 강조 + 사이드 패널에 목록(개수와 함께) 표시, 클릭 시 카메라 포커스 이동.
- 드래그 중에는 근처 호환 기어와의 관계를 초록(연결 가능)/빨강(불가능) 고스트 하이라이트로 실시간 미리보기.

## 5. 내구도 & 시간배율 시스템

- 내구도 소모 = `기어별 기본 마모율 × (부하 여부에 따른 가중치) × 사용자 시간배율 × 경과 시간`. 부하 오브젝트가 걸린 하위 트리는 마모가 더 빠르다.
- **시간배율 슬라이더**(예: 0.1배~10배)로 마모가 소모되는 속도를 조절 — 실제 회전 애니메이션 속도와는 별도 파라미터로 둔다(회전은 그대로 보되 마모만 빨리감기 가능하게).
- 시각화: 기어 표면 색을 남은 내구도 비율에 따라 초록→노랑→빨강으로 실시간 그라데이션 처리. 클릭/호버 시 사이드 패널에 정확한 수치(현재/최대, 타입) 표시.
- 내구도가 0에 도달하면 해당 기어는 **회전을 멈추고 파손(균열 텍스처) 표시**로 전환되며, 그 하위로 동력이 끊긴다 — 트리 전체에 실질적 영향을 준다.

## 6. 인터랙션 & UI

- **팔레트 패널**: 6종 기어를 아이콘으로 나열, 드래그해서 3D 바닥에 새로 배치.
- **재배치**: 기존 기어도 클릭+드래그로 이동 가능, 뗄 때 주변과 맞물림 재판정.
- **카메라**: 드래그로 궤도 회전, 휠/핀치로 줌인·줌아웃(요청하신 화면 스케일 기능).
- **모바일**: 터치 드래그로 기어 이동, 두 손가락 핀치 줌.
- **저장/불러오기**: 브라우저 로컬 저장(자동/수동) + JSON 파일 내보내기/가져오기로 다른 기기 이동 지원.

## 7. 아키텍처 & 기술 스택

- **렌더링**: Three.js(WebGL) — `OrbitControls`로 카메라 궤도 회전 + 줌, 절차적 기하(procedural geometry)로 각 기어 타입의 이(teeth) 형상을 생성.
- **빌드**: Vite + TypeScript.
- **시뮬레이션 코어**(맞물림 판정, 회전 전파, 마모 계산): 렌더링/DOM과 분리된 순수 TypeScript 모듈. 입출력이 고정된 함수형 인터페이스로 작성해 향후 교체 가능하게 한다.
- **Rust/WASM 확장 자리**: 시뮬레이션 코어와 동일한 인터페이스로 Rust 크레이트를 병행 개발할 수 있는 자리를 처음부터 비워둔다(`crates/gear-sim-core/` 등). `wasm-pack`으로 빌드해 JS 구현과 런타임 스위치 가능하게 하고, 기어 수를 늘려 벤치마크한 뒤 실제로 필요할 때만 전환한다. 1차 구현 범위에는 포함하지 않음(YAGNI) — 인터페이스만 그 자리를 고려해 설계.
- **영속성**: 브라우저 `localStorage` + JSON export/import. 서버 없음.

## 8. 데이터 모델 (개략)

```ts
type GearType = "spur" | "helical" | "crank" | "bevel" | "worm" | "load";

interface GearInstance {
  id: string;
  type: GearType;
  position: [number, number, number];
  rotationAxis: [number, number, number];
  teeth: number;       // load 타입은 0
  module: number;       // 이 크기(맞물림 판정 기준)
  durabilityMax: number;
  durabilityCurrent: number;
}

interface MeshEdge {
  a: string; // GearInstance.id
  b: string;
  ratio: number; // teeth 비율로 계산된 각속도 전달 비
}
```

## 9. 테스트 접근

- 시뮬레이션 코어(맞물림 판정, 회전 전파, 마모 계산)는 렌더링과 독립적인 순수 함수라 **단위 테스트로 충분히 커버 가능** — 좌표/잇수를 입력해 유효/무효 맞물림, 회전 방향/속도, 마모 누적을 검증.
- 렌더링/UI는 수동 QA(브라우저에서 배치→연결→회전→마모 시나리오 확인) 위주로 진행.

## 10. 향후 확장 후보 (이번 범위 아님)

- Rust/WASM 시뮬레이션 코어 전환(6장 참고)
- 추가 기어 패밀리(랙&피니언, 유성기어, 래칫/원웨이 기어 등)
- 파손 이펙트 고도화(파티클 등)
